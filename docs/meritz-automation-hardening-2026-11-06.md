# 메리츠 자동매매 안정화 계획과 검토

2026-11-06, Claude 데스크톱의 기존 `자동매매 로직 코드 리뷰` 세션에서 계획을 검토받았다. 판정은 **A~D 보완을 반영하는 조건부 승인**이었다. 보완 범위를 전달한 뒤 Claude는 “이대로 진행해도 됩니다”라고 확인했다. 구현은 Codex가 담당하며 로컬 변경·모의 검증까지만 진행한다.

## 수정 범위

1. 준비·제출의 중복 검사에서 종목을 먼저 거르고, 명확한 과거 미국 거래 세션의 주문만 제외한다. 같은 세션·미래·휴장일 주문은 계속 검사하고 SOXL 접수시각 불명은 중단한다.
2. 주문 요청의 `fetch` 직전에 송신 단계를 기록한다. 주문 전송 전 실패만 기존 `rejected` 상태와 `transmission: not_sent`로 기록한다. 전송 후 응답·저장 불명은 `unknown`을 유지하며 자동 재전송하지 않는다.
3. 취소 전에 전체 대상의 취소 가능 여부와 남은 시간을 검사한다. 취소 행 증가에 따른 페이지 수, 관측 응답 지연, DB 작업, 취소 확인 30초, 잔고 확인 15초, 새 주문을 예산에 포함한다. 취소 직전 최신 조회도 유지한다.
4. 취소 확인과 자금 반환은 정해진 시간 안에서 간격을 늘려 재조회한다. 전량 취소 확정·원주문 잔량 0·기존 버전 및 수량 검증을 통과해야 새 주문을 보낸다. 공식 주문일자는 DB와 메모리에 함께 반영한다.
5. 실패 알림에는 취소 접수·확정 및 새 주문 접수 건수를 남긴다. 잔존 주문을 확인하지 못했으면 없다고 단정하지 않는다. 실패 상태 저장과 알림 전송은 별도로 처리한다.
6. 워치독은 브로커 잠금을 획득하거나 브로커 API를 호출하지 않는다. 진행 상태와 활성 잠금을 보면 DB만 최대 약 270초 재조회해 완료를 기다린다. 정체와 종료 실패를 구분하며 본 작업 잠금 실패도 알린다.
7. 시작 허용 시간은 한국 22:00~22:02:59, 03:00~03:04:59다. 워치독은 각각 05~09분에 시작할 수 있다. 밤 주문 제출은 22:05 전, 모든 주문은 기존 정규장·휴장·마감 제한을 유지한다.
8. 밤 자동주문 준비 전에 이전 세션의 미처리 체결을 날짜순으로 복구한다. 수동 미리보기는 기존 직접 입력 대조만 수행한다. 필요한 유효 종가가 없으면 모드 전환 없이 한 번 갱신한 뒤 재확인한다.

## Claude 승인 조건 A~D의 반영

- **A — 낡은 기준 상태:** 아침·밤이 함께 사용하는 체결 반영 루프에서 앞선 날 처리에 성공했고, 다음 날이 pending이며 API run·직접 체결·해당 세션 증권사 주문이 모두 없는 경우에만 기준 상태와 가이드를 갱신한다. 기존 review나 거래 이력이 있는 날은 강제로 바꾸지 않는다.
- **B — 워치독 오탐:** 진행 중인 작업이 끝날 시간을 기다린 뒤 판정한다. 시간 안에 끝나지 않으면 진행 중 상태로 남았다고 알린다.
- **C — 시간 예산:** 취소 행으로 늘어날 조회 페이지와 DB 비용도 포함한다. 32건 정상 지연과 다페이지·시간 부족 시나리오를 구분해 검증한다. 시간이 부족하면 취소를 시작하지 않는다.
- **D — 세션 필터:** 다른 종목의 잘못된 접수시각 때문에 SOXL 주문을 막지 않는다. 과거 거래일로 명확히 확인되지 않는 주문을 단순히 필터에서 버리지 않는다.

## 보존하는 규칙과 남은 한계

SOXL 20분할, 리버스 별지점, T 계산, 부분체결 수동 확인, 계좌·보유량·버전 검증, 주문 identity와 DB 고유키를 유지한다. 기존 CSS 변경은 이번 작업과 무관하다.

예상 시간은 미래 응답 지연을 보장하지 않는다. 취소 후 새 장애가 발생하면 자동 재개하지 않고 알려진 처리 건수와 확인 필요 알림을 남긴다. 다일 미처리 중 오래된 날의 라운드가 종료되면 현재 현금을 과거 거래에 임의 배분하지 않고 한국어 안내와 함께 중단한다. Cron 설정·운영 플랜·실제 메리츠 취소 응답은 이번 로컬 수정에서 변경하거나 검증하지 않는다.

검증 대상은 브로커·매매 규칙 테스트, 실제 서비스 함수에 대한 모의 DB/브로커 흐름, build, typecheck, diff 검사다. 실주문은 검증 수단으로 사용하지 않는다.

## 로컬 검증 결과

- `node --import tsx --test src/lib/broker/*.test.ts src/lib/trading/*.test.ts`: 116개 통과, 실패 0개.
- `npm run build`, 빌드 후 `npm run typecheck`, `git diff --check`: 통과.
- 모의 시간 기준 워치독 270초 대기 + 알림 지연 20초 = 290초. 실제 플랫폼·DB·푸시 지연을 보장하는 측정은 아니다.
- 22:02:59 시작 시 복구 지연을 110초·116초·125초로 나누어 정상 제출·일부 제출 후 중단·전송 전 중단을 검증했다. 호출 간격 대기 후에도 실제 POST 직전에 제출 시각을 다시 검사한다.
- 커밋·푸시·배포, 운영 DB 변경, 실제 브로커 조회·취소·주문은 하지 않았다.

## 2026-11-07 보완매수 묶음

브로커 작업 한도는 기존 240초로 유지한다. 보완매수만 높은 가격부터 묶으며, 그룹 최고가 대비 최저가 차이가 3% 이하인 경우에만 같은 그룹에 넣는다. 인접 가격의 차이가 작다는 이유로 그룹 폭을 늘리지 않는다. 묶음 가격은 그룹 최저가, 수량은 원래 수량 합계다. 기본매수와 매도는 가격·수량을 바꾸지 않는다.

API 주문은 현재가 상한·하한 필터 → 보완매수 묶음 → 현금 범위 제외 순서로 처리한다. 원래 가이드 항목은 sources에 보존해 자금 검사, 취소·교체, 체결 후 T 적용에 사용한다. 가이드 화면의 기존/묶음(3%) 선택은 표시만 바꾸며, API 주문 방식이나 자동매매 설정을 변경하지 않는다. 화면 가이드는 원래 가격을 보여주고 API 미리보기에서 실제 현재가·현금 조건을 추가 적용한다.

## 2026-11-07 추가 경계 수정

- 하락 보완매수 가이드의 최초 보기는 묶음(3%)이다. 기존 보기도 선택할 수 있다.
- 취소 접수 0건이며 미전송 또는 명확한 거절로 확인되면 기존 주문 유지로 안내한다. 취소 POST 이후 응답 유실·불명확한 접수는 0건이라도 기존 주문이 살아 있다고 단정하지 않고 미확인 안내를 유지한다.
- 중복 검사에서 무시하는 과거 주문은 뉴욕 날짜가 지난 거래일이고 그날 정규장 마감 전에 접수된 주문뿐이다. 마감 정각부터는 다음 세션 예약일 수 있으므로 차단한다. 표준시·서머타임·조기폐장의 실제 마감 시각을 사용한다. 체결 반영용 brokerSession의 날짜 의미는 변경하지 않는다.
- 매수·매도·취소 POST는 호출 간격 대기와 최종 검사 뒤 남은 시간이 15초 미만이면 fetch를 호출하지 않는다. 이는 rejected / transmission:not_sent로 기록되며 자동 재전송하지 않는다. 정확히 15초 이상이면 송신하고 고정 15초 응답 한도를 사용한다. 조회 요청만 기존 작업 마감에 맞춰 응답 한도를 줄인다. 작업 한도 240초·서버 300초·계좌 잠금 5분은 유지한다.
