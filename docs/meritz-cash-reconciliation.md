# 메리츠 현금 차액과 라운드 원금

라운드 전량매도 체결을 검증한 뒤 USD 추정 예수금으로 현금을 대조한다.
복리는 그 현금 전액을 다음 라운드 원금으로 사용한다. 단리는 기존 원금에
현금 차액만 적용한다. 매매 체결로 계산한 종료 현금과 라운드 손익은 보존하고,
별도 입출금 이력에 `라운드 종료 후 현금 증가/감소`를 남긴다.
순차적으로 체결을 반영한 상태와 비교하므로 매수·매도를 인출로 오인하지 않는다.

API는 `/accounts/v1/me/overseas/currencies`의 USD 행
`estm_frcr_amt`를 사용한다. 결제 전후 차이가 있는 `frcr_amt`,
주식 평가금액, 주문 예약에 영향받는 주문가능금액은 원금 대조에 사용하지 않는다.
잔액만으로 이자·수수료·입금·인출의 원인을 구별할 수 없어 차액으로 기록한다.

## 주문 전 5% 감소

이전 거래일 체결 검증 → 전략 재조회 → 당일 중복 주문 확인 → 현금 대조 →
원금·T·모드 갱신 → 당일 가이드 재생성 → 미리보기 → 제출 직전 재확인 순서다.

- 비교: `API 현금 <= 앱 현금 × 0.95` (정확히 5%도 포함).
- 차액: `Δ = API 현금 - 앱 현금`.
- 새 원금: `P' = P + Δ`.
- 새 T: `T' = T × P / P'` (무보유는 0).

기존 T가 뜻하는 투입 단위 금액 `T × P / 분할 수`를 유지한다.
현재 주가나 평가손익은 원금으로 섞지 않는다. 보유수량·평단도 유지한다.
예: 원금 $10,000, T=10, 현금 $5,000에서 $1,000 인출 시
원금 $9,000, T=11.1111111111. 정상 모드에서 T가 `분할 수 - 1`을
초과하면 기존 규칙대로 리버스 진입한다.

5% 미만 감소·현금 증가는 라운드 중에 T를 바꾸지 않는다.
앱 현금을 매일 덮어쓰지 않으므로 소액 감소가 누적돼 5%에 도달하면 감지한다.
매수 전 무보유 상태에서는 종료된 라운드의 현금을 다시 대조하므로,
종료 검증 이후 들어온 입금도 첫 주문에 반영된다.
확인 창이 열린 뒤 임계값 이상으로 현금이 바뀌면 기존 미리보기를 만료시키고
새 가이드 확인을 요구한다.

## 저장과 방어

- 기존 예약 입출금을 먼저 적용한 뒤 실제 예수금과 비교해 이중 반영을 막는다.
- 체결·라운드 저장·차액 이력을 하나의 DB 트랜잭션으로 처리한다.
- 수동 입력 체결의 대조도 라운드 현금 갱신과 함께 저장한다.
- 원금 0 이하, 미확인 USD 잔액, 오래된 전략 버전, 미반영 과거 거래일은 거절한다.
- 기존 SOXL 20분할 전략 하나만 사용하며, SOXL 이외의 보유종목 또는 수량 불일치는 대조 후 처리한다.
- 현금 차액은 매매손익과 분리하지만 이자와 외부 입금의 세부 분류는 하지 않는다.
- 수동 체결 입력은 시장 데이터 갱신 뒤 대조를 요청한다. 당일 장 마감 전에는
  기존 체결 검증 시간 제한을 따르며, 장 마감 후 스케줄러 또는 대조 요청으로 처리한다.

적용 파일: `supabase/migrations/20261104230234_meritz_cash_reconciliation.sql`.
운영에는 이 마이그레이션을 먼저 적용한 다음 앱 코드를 배포한다.
