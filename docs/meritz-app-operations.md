# LTH 메리츠 연동 사용·운영

구현 기준: 2026-11-02, 운영 반영: 한국시간 2026-11-03. 운영 주소는 https://lth-six.vercel.app 이다.

서버 주문 키를 다루는 기능 추가와 함께 기존 Next.js 16.2.9를 보안 수정판 16.4.4로 업데이트했다. 근거: [접속 보호 우회 수정](https://github.com/advisories/GHSA-6gpp-xcg3-4w24), [이미지 처리 보안 수정](https://github.com/advisories/GHSA-2464-fhr4-w9xw).

## 화면과 실행 방식

- 상태 탭의 네비게이션 바로 아래에 **자동매매** 토글이 있다.
- 정규장 개장 전 켜면 그 거래일, 개장 시각 이후 켜면 다음 미국 거래일부터 적용한다. 휴장일·서머타임을 반영한다.
- 주문 탭의 **API 주문**은 토글과 별개다. 현재가와 계좌를 조회하고 실제 가격·수량을 팝업으로 보여준다. 사용자가 `주문 전송`을 눌러야 전송한다.
- API 주문은 정규장 개장 후부터 마감 10분 전까지 사용할 수 있다. 같은 거래일 가이드는 한 번만 제출한다.
- 자동매매를 꺼도 이미 접수한 주문은 취소하지 않는다. 체결 자동 조회·반영은 유지한다.
- 같은 계좌의 같은 종목은 전략 하나에 연결한다. 상태 탭을 열어 연결한 전략이 자동 체결 조회 대상이다. 연결 시작 미국 거래일 이전의 이력을 임의로 소급 입력하지 않는다.

## 공통 주문 규칙

- 오늘 가이드의 LOC·LIMIT·MOC 유형을 유지한다.
- 매수 가격이 현재가 +20%를 초과하면 +20% 선으로 내린다. 같은 가격이 된 기본·보완매수 수량을 합쳐 중복 없이 제출한다.
- 보완매수는 현재가 -10% 이상 가격만 남긴다. 정확히 -10%는 포함한다.
- 매도 가격이 현재가 +20% 이상이면 해당 주문은 제외한다. MOC는 가격 필터에서 제외한다.
- 현금·보유수량이 부족하면 임의 환전이나 주문 금액 증액을 하지 않고 오류를 표시한다. 기존 미체결을 포함한 증권사 현금 예약도 확인한다.
- **모든 메리츠 호출을 직렬 처리하고 최소 1초 간격을 둔다.** 계좌별 DB 잠금과 호출 시각 예약으로 수동·자동 작업 및 서로 다른 서버 실행 간에도 간격을 유지한다.
- 경고·거절·응답 유실은 성공으로 표시하지 않는다. 전송 후 응답이 없으면 주문내역과 대조하며 자동 재전송하지 않는다.
- 성공 문구는 주문 **접수** 성공이다. LOC 체결은 장 마감 후 실제 내역으로 확인한다.

## 수동 주문도 체결 자동 입력되는가

토글 OFF여도 연결한 전략의 체결을 조회한다. API 버튼으로 낸 주문은 저장한 주문번호에 연결한다. 메리츠 앱에서 낸 주문도 연결된 종목이고 당시 가이드의 가격·수량·유형과 연결이 명확하면 자동 반영한다.

이미 LTH에 수동 입력한 체결은 매수·매도 수량과 금액을 대조해 중복 입력하지 않는다. 다음은 자동으로 추정해 덮어쓰지 않고 확인 대기로 남기며 알림을 보낸다.

- 가이드와 다른 임의 수량·가격으로 낸 외부 수동 주문
- 부분체결, 소수점 체결, 정정·취소 주문에 걸린 체결
- 반회/1회 매수의 의미가 불분명한 내역
- 체결 전 상태에 입출금·수동 수정이 있어 버전이 달라진 경우
- 기존 수동 입력과 메리츠 수량·금액이 서로 다른 경우

현재 LTH의 현금 계산은 기존 수동 입력과 같은 **체결금액 기준**을 유지한다. 수수료를 임의로 추정해 추가 차감하거나 계좌 전체 예수금으로 전략 현금을 덮어쓰지 않는다. 주문 전에는 증권사 주문 가능 현금을 별도로 확인한다.

## 아침 처리

기존 UTC 21:10 월~금 작업(한국 화~토 06:10)에서 차트를 갱신하고 연결 전략의 미반영 거래일을 순서대로 조회한다. 날짜 범위 이력과 주문 상세의 실제 체결번호를 사용한다. 한국시간 주문 시각을 미국 거래일과 연결하되, 메리츠 상세 조회용 주문일자는 그대로 유지한다.

체결·스냅샷·현금·평단·T·라운드·체결 식별자 저장은 한 DB 트랜잭션으로 처리한다. 캔들 갱신이 연결 전략의 리버스 모드를 먼저 바꾸지 않도록 분리했다. 매수·보완 주문 여러 건이 체결돼도 T는 주문 건수만큼 증가하지 않는다.

수동/자동 동시 입력은 기존 전략 버전 검사로 충돌을 감지한다. 확인이 필요한 이전 거래일이 있으면 다음 자동 주문을 보류한다.

## 알림

앱 상단 `알림`에서 주문 접수·체결 반영·오류 내역을 확인한다. 상태 탭의 `알림 받기`로 이 기기의 푸시를 연결한다.

아이폰은 iOS 16.4 이상에서 HTTPS 앱을 **홈 화면에 추가**한 뒤 알림을 허용해야 한다. 앱 종료 상태·잠금화면 수신은 실제 아이폰에서 별도로 검증해야 한다. OS 알림 설정·집중 모드·통신 상태에 따른 표시를 서버가 보장하지는 않는다.

## 서버 설정

| 변수 | 용도 |
|---|---|
| `MERITZ_APP_KEY`, `MERITZ_APP_SECRET` | 메리츠 계좌 연결. 서버 전용 |
| `APP_PASSWORD` | 운영 앱의 접속 보호. 운영 주문 기능에 필요 |
| `CRON_SECRET` | 예약 작업 인증 |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` | 푸시 키 쌍. 같은 키를 유지해야 기존 구독을 재사용 가능 |
| `VAPID_SUBJECT` | 운영 앱의 HTTPS 주소 또는 운영자 본인의 mailto 연락처 |
| `MERITZ_MAC_ADDRESS` | 선택. 12자리 MAC 주소 |

키는 클라이언트·로그·알림에 노출하지 않는다. 새 DB 테이블은 RLS를 켜고 서버 `service_role`만 접근한다.

푸시 키 생성:

```bash
npm run setup:broker:push
```

이 명령은 키를 로컬 `.env.local`에 저장하며 출력하지 않는다. 운영 Vercel 환경에도 같은 키를 등록하고 `VAPID_SUBJECT`는 실제 운영 앱 주소로 설정해야 한다. 로컬 테스트 기본값 `https://localhost`를 운영 연락처로 복사하지 않는다.

앱 연동은 주문 스크립트의 `MERITZ_READ_ONLY` 변수와 별개다. 운영 주문은 앱 접속 보호, 전략별 자동매매 설정, 사용자 확인, 주문 중복 방지로 제어한다. 로컬 검증에서는 주문 전송을 실행하지 않는다.

## 예약 실행과 배포 범위

개장 후보는 UTC 13:30 / 14:30이며 뉴욕 현지시각 09:30인 실행만 진행한다. 5분 뒤 작업은 실행 누락을 확인해 경고하며 늦은 주문을 대신 내지 않는다. 미국 휴장일과 메리츠 장운영 상태를 함께 확인한다.

현재 Vercel 요금제의 시 단위 예약 정밀도를 피하기 위해 개장·5분 후 점검 4개 작업은 기존 Supabase의 `pg_cron` + `pg_net`으로 등록했다. 뉴욕 09:30에 해당하는 후보만 앱에서 처리한다. 정각 특정 초까지 보장하지는 않는다. 아침 차트·체결 작업은 기존 Vercel Cron을 유지한다. 호출 중복·누락에 대비해 일일 기록·계좌 잠금·체결 대조를 함께 사용한다.

예약 대상은 메인 `lth`의 `https://lth-six.vercel.app`으로 고정했다. 인증값은 Supabase Vault의 `lth_meritz_cron_secret`에 저장했으며 메인 운영 `CRON_SECRET`과 일치해야 한다. 운영 인증값 변경 시 Vault도 함께 갱신한다. 다른 배포로 복사할 때 이 예약 SQL을 그대로 적용하지 않는다.

`net`은 Data API에 공개하지 않는 관리용 스키마다. 요청 대기 중에는 인증 헤더가 큐에 존재하므로 DB 직접 접속 권한은 관리자에게만 유지한다. 주문·체결을 저장하는 앱 테이블의 RLS와 서비스 역할 전용 권한은 유지한다.

운영용 메리츠 키·접속 보호·예약 인증·VAPID 키 3개를 확인했다. 자동매매는 OFF로 배포했다. 상태 조회는 계좌 설정·체결 연결·푸시 준비가 정상임을 확인했으며, 실제 주문 전송과 아이폰 잠금화면 수신은 검증하지 않았다.

로컬 코드 작성, DB 스키마 적용, 테스트 통과가 배포·운영 실행 성공을 뜻하지는 않는다. 활성화·푸시 발송·실주문을 검증했다고 별도 증거 없이 보고하지 않는다.

## 검증 명령

```bash
npm run test:broker
npm run test:broker:ui
npm run build
npm run typecheck
```

브라우저 검증은 `/api/broker`와 `/api/notifications`를 모의 응답으로 대체하고 그 밖의 모든 POST도 차단한다. 실제 주문·토글·체결 기록을 변경하지 않는다.

기준 API: [메리츠 공식 명세](https://github.com/meritz-securities/open-api/blob/a93c6409db73ea97ad15f7b7186f36c9f32ecd89/openapi.json). 일정: [NYSE](https://www.nyse.com/markets/hours-calendars). 예약 정밀도: [Vercel](https://vercel.com/docs/cron-jobs/usage-and-pricing), [Supabase Cron과 Vault](https://supabase.com/docs/guides/functions/schedule-functions). iOS 푸시: [WebKit](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/).
