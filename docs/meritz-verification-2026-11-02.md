## 운영 DB 반영

LTH 프로젝트에 `20261102135702_meritz_trading.sql`에 해당하는 추가 스키마를 적용했다. 새 테이블 8개는 모두 RLS가 켜져 있으며 일반 공개 역할의 권한을 제거했다. 서비스 역할만 접근한다.

검증 후 실제 DB에서 자동매매 활성 전략 0개, 신규 앱 API 주문 0건, 신규 자동 반영 체결 0건임을 확인했다. 기존 잔고·체결을 테스트 데이터로 수정하지 않았다. 전략 연결과 체결 전 기준 상태만 OFF 상태로 저장했다.

보안 점검의 `RLS Enabled No Policy`는 서버 전용 테이블을 공개 클라이언트에서 차단하는 이 앱의 의도와 일치하는 정보 항목이다. 일반 역할 접근 차단은 별도 검증했다.

## 추가 보안 수정

기존 Next.js 16.2.9의 보안 권고를 확인해 공식 16.4.4 배포로 업데이트했다. 설치 후 npm 검사에서 critical·high 보고가 해소됐으며 빌드와 브라우저를 다시 확인했다. 빌드 도구의 `baseline-browser-mapping` 관련 moderate 항목 1개는 남아 있어 보안 보고 전체가 0이라고 주장하지 않는다.

요청 출처 검사는 내부 URL이 `localhost`로 정규화되어도 실제 Host와 브라우저 Origin을 대조한다. 로그인 후 이동 주소도 검증한 실제 Origin을 유지한다. 세션은 기존의 Host 결합·서명·HttpOnly 방식을 유지한다.

## 운영 반영

Vercel 팀 접근 허용 후 메인 `lth`에 소스 파일 방식으로 운영 배포했다. 다른 공유 프로젝트는 변경하지 않았다. 운영 URL은 https://lth-six.vercel.app 이다. 기존에 사용자가 수정한 차트 최소 높이 제거는 작업 폴더에 보존하고 이번 배포에는 포함하지 않았다.

운영 환경에 메리츠 키 두 개, `APP_PASSWORD`, `CRON_SECRET`이 등록된 것을 확인했다. VAPID 키 쌍과 실제 운영 URL의 연락 주소도 등록했다. 로그인 후 실제 운영 `/api/broker`·`/api/notifications`에서 HTTP 200, 설정 있음, 자동매매 OFF, 체결 연결 ON, 푸시 키 있음이 확인됐다.

개장·누락 점검은 기존 Supabase의 분 단위 Cron에 4개 예약으로 등록했다. 인증값은 Vault에 보관하며 예약 명령에 값 자체를 넣지 않았다. 앱의 뉴욕 시각·휴장일 검사와 전략별 토글이 실제 처리 여부를 결정한다. 기존 아침 Vercel 예약은 유지했다. 유료 요금제 변경은 하지 않았다.

한국시간 2026-11-03 00:05에 별도의 일회성 예약으로 앱 manifest 조회가 자동 실행됐다. Cron 실행 상태 `succeeded`, HTTP 200을 확인했고 검증 예약은 스스로 삭제됐다. 주문 경로는 이 테스트에서 호출하지 않았다.

인증된 운영 화면도 390px·320px·1280px에서 확인했다. 토글 위치·OFF 표시·주문 버튼·알림 버튼·가로 넘침 없음·브라우저 오류 없음이 통과했다. 이 검사에서는 모든 변경 요청을 차단했다. `.codex/production-verification/`에 캡처와 결과가 있다. 초기 배포 실행 오류 로그 조회에서는 error/fatal 기록이 없었다.

## 아직 검증하지 않은 것

- 실제 주문 접수·체결을 이 앱 코드로 실행하지 않았다. 주문 미리보기와 성공/오류 흐름의 확인은 모의 검증이다.
- 자동매매를 켜지 않았다. 개장 예약은 등록했지만 활성 전략이 0개이므로 주문은 내지 않는다.
- 물리적 아이폰의 홈 화면 설치·권한 허용·잠금화면 푸시 수신은 미검증이다.
- 정규장 개장 자동주문과 다음 아침의 실제 체결 반영은 실거래가 있어야 확인할 수 있으므로 모의 검증과 구분한다.

수동 주문이 가이드와 다르거나 부분·소수점·정정 체결, 전략 버전 불일치가 발생하면 자동으로 T를 추정하지 않고 확인 대기로 남긴다. 이는 정상적인 안전 처리이며 일반 체결 자동 반영과 구분해 표시한다.
