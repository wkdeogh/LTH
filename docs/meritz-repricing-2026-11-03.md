# 한국 22시 1차 주문 · 03시 재점검

사용자 확인: 1차도 한국 밤 10시로 변경. 사용자는 전날 약 22시 API 주문 접수를 확인했다고 알려주었다. 이 구현 검증에서 실제 주문·취소를 실행한 것은 아니다.

## 동작

- 한국 22:00 1차 자동주문. 당일 가이드와 기존 +20% 매수 상한 / -10% 보완 하한 / +20% 이상 매도 제외를 유지한다. API의 정규장 닫힘 코드 012는 이 시간의 자동주문 경로에서만 허용한다. 접수는 정상 응답·경고 0·주문번호로 판정한다.
- 한국 다음 날 03:00 SOXL의 최신가와 1차 실제 제출 직전에 조회·저장한 현재가를 비교한다. 1차 지정가와 비교하지 않는다.
- `abs(new - initial) * 100 > initial * 5`에서만 취소·교체한다. 가격을 1/10000 달러 정수로 비교해 정확히 5%인 값은 유지한다.
- $80 → $84 또는 $76은 유지. $84.01 또는 $75.99면 교체한다.
- 취소 대상은 앱에 기록된 동일 계좌·미국 거래일의 1차 SOXL 주문이다. MTS·스크립트 주문을 임의로 취소하지 않는다.
- 전량 기체결된 주문은 가이드에서 빼고 기체결 수량·금액을 계좌 대조에 반영한다. 부분체결, 외부 수동 주문·정정·취소가 있으면 확인 대기로 보류한다.
- 취소 의도를 DB에 먼저 기록하고 요청한다. 경고·거절·응답 유실은 재전송하지 않는다. 취소 접수 성공만으로 교체하지 않고, 원주문의 취소 확정 수량이 전체 수량과 일치하며 체결·미체결 잔량이 0임을 조회한 뒤 새 주문을 낸다. 확인되지 않으면 남은 주문 상태를 경고하고 새 주문은 보내지 않는다.
- 취소 중 전략·토글·새로운 수동 주문·체결이 바뀌면 보류한다. 취소 후 예수금·보유·매도 가능 수량과 최신 가격 범위를 다시 확인한다.
- 당일 가이드를 03시 가격으로 다시 처리하며 주문 유형 LOC/LIMIT/MOC를 유지한다. 주문 금액·수량을 임의 증액하거나 시장가로 바꾸지 않는다.
- 동일 거래일의 03시 작업과 원주문별 취소 요청은 각각 고유 키로 한 번만 처리한다. 모든 메리츠 호출은 기존 계좌 잠금과 최소 1초 간격을 사용한다.
- 22:05와 03:05 작업은 누락·중단을 경고하며 늦은 주문을 대신 내지 않는다. 22시 이후 ON은 다음 미국 거래일에 적용한다. OFF이면 03시 취소·재주문도 하지 않는다.
- 미국 휴장일과 03시에 이미 닫힌 조기 폐장일에는 교체하지 않는다. 아침에는 두 차수의 실제 체결을 같은 거래일로 모아 기존 T·현금·평단·라운드 원자적 반영을 한 번 수행한다. 공식 주문일자와 시각으로 자정 전후 반복 주문번호를 구분한다.

## 검증

기존 계산·인증 단위 검사와 새 재주문·DB 권한·중복·취소 순서 검사를 합쳐 70개 통과. 빌드와 타입 검사 통과. 기존 UI를 변경하지 않았다. 실제 증권사 취소와 03시 자동 교체는 모의 검증이며 실거래 검증으로 보고하지 않는다.

예약: 기존 Supabase Cron에서 UTC 13:00, 13:05, 18:00, 18:05 월~금. 메인 `lth`만 대상으로 하고 아침 차트·체결 Vercel Cron은 유지한다. CRON_SECRET은 기존 Vault 값을 사용한다. 구 개장 시각 후보 예약 4개는 새 예약으로 교체한다.
